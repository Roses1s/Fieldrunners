# Как запустить и протестировать Field Defense

Нужен только **Node.js ≥ 18** (проверено на v22). Никаких зависимостей ставить не надо —
`npm install` не требуется, все тесты и сборка работают на стандартной библиотеке Node.

```bash
node -v          # должно быть v18 или выше
cd field-defense
```

---

## Способ 1. Дев-сервер (модульные исходники, горячая правка)

```bash
node tools/serve.mjs 8080        # или: npm run dev
```

Сервер слушает `0.0.0.0:8080` и печатает:

```
FIELD DEFENSE dev server → http://0.0.0.0:8080/
single-file build        → http://0.0.0.0:8080/dist/index.html
```

Открывать:

| URL | Что это |
|---|---|
| `http://localhost:8080/` | игра из модулей `js/**` — правите файл, обновляете страницу |
| `http://localhost:8080/?debug=1` | то же + отладочная плашка (FPS, шаги/кадр, сущности, пулы) |
| `http://localhost:8080/dist/index.html` | собранный единый файл |

Заголовок `Cache-Control: no-cache` отдаётся на все файлы, так что кэш браузера мешать не будет.
Другой порт: `node tools/serve.mjs 3000` или `PORT=3000 node tools/serve.mjs`.

---

## Способ 2. Единый файл (офлайн, работает даже с `file://`)

```bash
node build.mjs                   # или: npm run build
```

На выходе `dist/index.html` — один самодостаточный файл (~393 КБ): CSS, весь код (54 модуля
склеены, `import`/`export` вырезаны), без единой внешней ссылки. Сборщик сам прогоняет
`node --check` по результату и ругается, если что-то сломалось.

Его можно:

- открыть двойным кликом с диска (протокол `file://` — работает, потому что внутри обычный
  `<script>`, а не ES-модули);
- скинуть на телефон (Telegram, почта, USB, Google Drive) и открыть в Chrome;
- залить на любой статический хостинг.

Service Worker регистрируется **только по `http(s)`** — с `file://` игра работает без офлайн-кэша,
но полностью работоспособна.

## Способ 3. Проверить на реальном телефоне (Samsung A56)

Три варианта, от простого к надёжному:

**A. С телефона по локальной сети (лучший вариант — настоящий Chrome, настоящие жесты).**

1. На компьютере: `node tools/serve.mjs 8080`.
2. Узнать IP компьютера в той же Wi-Fi-сети:
   - Windows: `ipconfig` → «IPv4-адрес»;
   - macOS/Linux: `ip addr` или `ifconfig` → `192.168.x.x`.
3. На телефоне в Chrome открыть `http://192.168.x.x:8080/`.
4. Если не открывается — проверьте, что телефон и компьютер в одной сети (не в гостевой),
   и что файрвол разрешает входящие на порт 8080.

**B. Файлом.** `node build.mjs` → отправить себе `dist/index.html` в Telegram/почту →
открыть на телефоне. Плюс: не нужен компьютер рядом. Минус: Chrome может отказаться
запускать локальный файл из загрузок — тогда помогает открыть через «Файлы» или
положить файл в папку, которую видно как веб-страницу.

**C. Публичный хостинг (нужен для `screen.orientation.lock` и полного экрана).**
Блокировка ориентации по стандарту работает **только в fullscreen**, а fullscreen
браузер разрешает далеко не во всех контекстах. На GitHub Pages / Netlify / любом
статике это работает лучше всего:

```bash
node build.mjs
# закоммитить dist/ и включить GitHub Pages на ветку/папку, либо:
npx --yes serve dist      # локальная имитация статики
```

Что обязательно проверить на телефоне (это и есть смысл мобильного теста):

- [ ] нет горизонтального скролла и «резинового» оттягивания страницы;
- [ ] HUD не залезает под вырез камеры и под скругления (safe-area);
- [ ] кнопки реально ≥ 44×44 px и попадают под палец;
- [ ] щипок зумит плавно, без рывков; драг панорамирует;
- [ ] радиальное меню открывается под пальцем и не уходит за край экрана;
- [ ] двойной тап строит башню мгновенно, минуя меню;
- [ ] звук появился **после первого тапа** (до тапа браузер его блокирует — это норма);
- [ ] сворачивание приложения / входящий звонок → автопауза, звук выключен;
- [ ] поворот в портрет → оверлей «поверните телефон»;
- [ ] FPS на 120 Гц: открыть `?debug=1` и смотреть счётчик (логика фиксированная 1/60,
      рендер может идти и 120 кадров/с);
- [ ] на 15–20 волнах (много врагов + Tesla) нет просадок.

## Автоматические тесты

Тесты гоняют **реальный код игры** на собственных моках DOM и Canvas2D — браузер не нужен,
сети нет, зависимостей нет.

```bash
npm test                 # build + sim + render + boot + bundle (212 проверок)
npm run test:all         # то же + баланс-бот (дольше всех)

node tests/sim.mjs       # 99  — логика, включая новые башни и разблокировки
node tests/render.mjs    # 61  — отрисовка, 109 процедурных спрайтов
node tests/boot.mjs      # 35  — интеграция: загрузка, ввод, игровой цикл
node tests/bundle.mjs    # 17  — собранный dist/index.html реально стартует
node tests/balance.mjs   # бот-автоигрок: 20 волн на всех 4 картах
```

| Набор | Что проверяет | Сколько идёт |
|---|---|---|
| `tests/sim.mjs` | сетка и типы клеток, A* и flow-field, запрет блокировки пути, пересчёт маршрутов при постройке/продаже, состав волн, экономика (награды, продажа 0.75, ранний вызов), формула урона `max(1, dmg − armor)`, замедление не стекается, burn-тик 0.5 с, десант транспорта, регенерация босса, звёзды, пулы | ~1 с |
| `tests/render.mjs` | что все 109 спрайтов генерируются, фон запекается в offscreen для 4 биомов, боевой кадр рисуется целиком, радиальное меню и панель башни, зум, экраны меню/карт/паузы/итогов, HUD вписан в 5 размеров экрана (включая 780×360 — A56) и элементы не перекрываются, все примитивы `Draw.js`, `towerStats`/`targetLabel` для всех башен × 3 уровней | ~1 с |
| `tests/boot.mjs` | реальные `Game` + `TouchInput`: init, тапы меню → карты → бой, радиальное меню, дабл-тап, панель улучшения/продажи, drag/pinch/wheel, кнопки HUD, пауза, `visibilitychange`, resize, 60 с боя на ×3, пулы не растут | ~5 с |
| `tests/bundle.mjs` | берёт собранный `dist/index.html`, запускает inline-скрипт в DOM/Canvas-моке, проверяет отсутствие import/export и 90 кадров без исключений | ~1 с |
| `tests/balance.mjs` | бот играет сам: ставит башни у текущих маршрутов, улучшает, вызывает волны досрочно, доходит до 20-й волны и печатает итог по каждой карте | ~12 с |

Ожидаемый результат — все строки `✔`, в конце `Провалено: 0`, код возврата 0.
Любой `✘` печатает имя проверки и причину; тесты падают с ненулевым кодом, поэтому их
можно повесить в CI одной строкой `npm test`.

Проверить баланс после правки чисел в `js/data/`:

```bash
node tests/balance.mjs
```

Он за секунды проигрывает все 4 карты целиком и печатает итог (волна, жизни, протечки, DPS,
звёзды, время). Ориентир последнего прогона: grasslands, desert и magma — 3 ★, city — 2 ★
(у бота есть случайный выбор башен, поэтому протечки гуляют). Если бот проигрывает на 5-й волне — стало слишком тяжело; если держит
20/20 жизней на всех картах без единого улучшения — слишком легко.

## Отладка в самой игре

| Инструмент | Как включить | Что показывает |
|---|---|---|
| Отладочная плашка | `?debug=1` в URL или клавиша **F** | FPS, зум, имя текущей сцены, стоимость кадра в мс, сколько шагов симуляции сделано за кадр (из бюджета); в бою дополнительно: враги, башни, снаряды, частицы, эффекты, номер и состояние волны, скорость, версия flow-field |
| Сетка клеток | клавиша **G** в бою | тип каждой клетки цветом (пусто / путь / заблокировано / башня / вход / выход), **стрелки flow-field** — куда пойдёт наземный враг, красный крест на проходимых клетках без маршрута (там строить нельзя), радиусы всех башен |
| Подсказка маршрута | автоматически на maze-картах | текущий кратчайший маршрут от входа к выходу |
| Сетка в режиме стройки | автоматически при открытом радиальном меню | зелёная подсветка клеток, где строить разрешено |
| Консоль | DevTools → Console | игра ничего не пишет в лог в нормальном режиме; любая ошибка там видна |

Плашка — это DOM-элемент `#debug` (не рисуется на canvas), обновляется дважды в секунду.

Горячие клавиши боя: `Space` — волна, `P`/`Esc` — пауза, `1/2/3` — скорость,
`U` — улучшить, `S` — продать, `T` — режим прицеливания, `G` — сетка, `F` — отладка.
В меню: `Enter` — играть, `←/→` — выбор карты, `Esc` — назад.

Объект игры всегда доступен в консоли как **`window.__game`** (не только в режиме отладки) —
это удобно, чтобы быстро дойти до поздних волн без ожидания:

```js
const s = window.__game.topScene;
s.gameSpeed = 3; s.speed = 3;   // ускорить время в 3 раза (нужно оба поля:
                                // gameSpeed — для HUD, speed — для игрового цикла)
s.economy.money = 999;          // денег на эксперименты

// Перемотать на 12-ю волну: волна стартует только из состояния «перерыв»,
// поэтому задаём номер и вызываем один раз (не в цикле — цикл не сработает).
s.waves.wave = 11;
s.sendNextWave();

window.__game.debugGrid = true;   // включить сетку (то же, что клавиша G)
```

Проверено: на 12-й волне спавнится 18 врагов, HP солдата = 93 (20 × 4.65), а без башен
за волну утекает 2 жизни — то есть скейл и экономика считаются честно.

Полезно для ручной проверки:

```js
s.enemies.length                       // сколько врагов живо сейчас
s.waves.state                          // BREAK | SPAWNING | FIGHTING | DONE
s.path.version                         // сколько раз пересчитывались маршруты
s.particles.count, s.projectiles.count // заполнение пулов
s.enemies[0]?.maxHp                    // HP врага с учётом скейла волны
Math.pow(s.hpScale, s.waves.wave - 1)  // накопленный скейл HP (1.15^(волна-1))
```

`s.hpScale` — это **база** множителя (1.15), а не накопленное значение: настоящий скейл
враг считает сам как `hpScale^(волна-1)`. На 12-й волне это ≈ 4.65, на 20-й ≈ 14.2.

### Пишете свой тест/харнесс

`Game.init()` **не запускает** игровой цикл — после него обязательно нужен `Game.start()`
(именно так делают `main.js` и `tests/boot.mjs`). Без `start()` кадры
`requestAnimationFrame` не идут, время стоит на нуле и волны не спавнятся — выглядит как
«игра зависла», хотя это просто не запущен цикл. Готовые моки DOM и Canvas2D берите из
`tests/dom-mock.mjs`: `setupDom({width, height, dpr, coarsePointer})` →
`{gameCanvas, runFrames(n, dtMs), elements, registry}`.

## Если что-то не так

| Симптом | Причина и решение |
|---|---|
| Пустая белая страница по `file://` на `index.html` | Это модульная версия — ES-модули по `file://` браузер блокирует (CORS). Откройте `dist/index.html` или запустите `node tools/serve.mjs` |
| `ERR_MODULE_NOT_FOUND` | Запускаете не из корня игры. Нужно `cd field-defense` |
| Порт 8080 занят | `node tools/serve.mjs 3000` |
| Нет звука | Браузер требует жеста: звук включается после первого тапа. Также проверьте кнопку звука в меню/паузе и системную громкость |
| Телефон не открывается по IP | Разные сети (гостевой Wi-Fi, мобильный интернет), файрвол, или IP сменился — проверьте `ip addr` заново |
| Ориентация не блокируется в ландшафт | `screen.orientation.lock()` работает только в полноэкранном режиме и не во всех браузерах. Это не баг игры: вызов обёрнут в try/catch, а в портрете показывается оверлей «поверните телефон» |
| Игра «залипла» после возврата из фона | Так задумано: по `visibilitychange` ставится автопауза. Нажмите «Продолжить» |
| Тесты падают после правки `build.mjs` | Сборщик режет `import`/`export` — если добавили новый файл, внесите его в массив `ORDER` в `build.mjs`, иначе в бандле не будет вашего кода |
| Правки не видны в браузере | Service Worker кэширует страницу. DevTools → Application → Service Workers → Unregister, или жёсткое обновление (Ctrl+Shift+R) |

## Короткий чек-лист «всё работает»

```bash
cd field-defense
node -v                     # ≥ 18
npm test                    # 212/212 ✔ (сначала сам пересобирает dist)
node tests/balance.mjs      # все 4 карты: ПОБЕДА (в последнем прогоне 3★/3★/3★/2★)
node build.mjs              # ✔ dist/index.html — ~393 КБ, 54 модуля
node tools/serve.mjs 8080   # → http://localhost:8080/
```

После этого — открыть в браузере, нажать «Играть», выбрать карту и дожить хотя бы до 5-й волны.
